# Review Training Readiness

Treat delivery readiness as more than content completeness.

## Readiness dimensions

### Content
- objectives align with agenda;
- demos support objectives;
- labs are relevant;
- assessment exists where needed.

### Lab readiness
- prerequisites explicit;
- steps executable;
- checkpoints clear;
- timing realistic;
- cleanup defined.

### Environment
- accounts created;
- licenses assigned;
- permissions verified;
- MFA tested;
- tenant/resource availability verified;
- required repos/files accessible.

### Delivery risk
- restricted access;
- network/proxy issues;
- trial expiration;
- blocked local tools;
- mismatched participant level;
- overfull agenda;
- fragile live demo dependencies.

### Instructor preparedness
- demo path rehearsed;
- fallback path exists;
- open questions resolved or consciously accepted;
- difficult concepts identified;
- timing buffers present.

## Status model

Return one:

- READY
- READY WITH RISKS
- NOT READY

## Output

Return:

1. readiness status;
2. blockers;
3. high-risk items;
4. unresolved questions;
5. required actions before delivery;
6. fallback plan;
7. instructor decisions;
8. confidence summary.

Never mark READY when a critical access or lab dependency is still unknown.
