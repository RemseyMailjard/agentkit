# Create Instructor Brief

This skill is intentionally delivery-focused.

The brief should help the instructor answer:

> What do I need to know and decide before I walk into the room?

## Preferred source types when available

- calendar event and attachments;
- earlier training notes and briefs;
- selected documents/files;
- relevant client email threads;
- previous delivery feedback;
- lab/environment notes.

## Required sections

### Client and training
- client;
- date/location/format;
- course;
- duration;
- participant count if known.

### Audience
- roles;
- baseline;
- expected depth;
- heterogeneity risks.

### Practical case flow
- main narrative;
- demos;
- labs;
- challenges.

### Environment and access
- tenant;
- accounts;
- licenses;
- permissions;
- local software;
- network restrictions;
- MFA/account expiry;
- test data.

### Likely blockers
Prioritize real delivery risks.

Examples:

- participant access missing;
- restricted Azure permissions;
- expired trial;
- blocked local MCP;
- Zscaler/proxy issues;
- missing repository access;
- insufficient licenses.

### Fallbacks
For each major blocker, identify a fallback such as:

- trainer-led demo;
- prebuilt environment;
- local/sample project;
- paper/design exercise;
- screenshots or recorded fallback only when necessary.

### Open questions
Only unresolved issues that matter before delivery.

### Instructor decisions
List decisions the trainer must make.

### Final checklist
A concise pre-delivery checklist.

## Style

Keep the brief concise, practical and skimmable.
Do not turn it into a full course manual.
