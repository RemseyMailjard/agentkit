# Design Training

Build the course from participant outcomes backwards.

## Core Skills4-IT flow

For each major concept prefer:

```text
hook / relevance
→ simple explanation
→ concrete example
→ deeper explanation
→ trainer demo
→ guided practice
→ independent practice
→ challenge
→ reflection / relevance
```

Do not force every step when the topic is simple, but preserve the progression from explanation to application.

## Course design workflow

1. Restate the target behavior.
2. Confirm audience and constraints.
3. Group learning objectives into coherent modules.
4. Sequence from foundational to applied.
5. Select realistic business/technical cases.
6. Decide where the trainer demonstrates.
7. Decide where participants practice.
8. Delegate detailed practical exercises to Lab Generator where available.
9. Add interaction questions and checks for understanding.
10. Add mini-challenges or quizzes.
11. Add assessment moments.
12. Reserve buffer for troubleshooting.
13. Include breaks and realistic pacing.
14. Add recap and work relevance.
15. Add optional depth for advanced participants.

## Training modes

### End-user/adoption training

Bias toward:

- short explanations;
- recognizable workplace scenarios;
- guided exercises;
- immediate productivity;
- low technical setup;
- confidence-building.

### Technical/professional training

Bias toward:

- architecture;
- implementation;
- hands-on labs;
- code/configuration;
- troubleshooting;
- constraints and failure modes;
- independent challenge;
- optional advanced depth.

## Practicality rule

Prefer approximately hands-on-heavy designs for technical training unless the request demands otherwise.

Do not create a training that is mostly lecture if participants are expected to build or operate something.
