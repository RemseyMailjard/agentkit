# Architecture Principles

- Prefer the smallest architecture that satisfies the capability and enterprise constraints.
- Treat identity, auth, network, data contracts, observability, testing and deployment as first-class.
- Separate capability boundaries from transport/protocol choices.
- Avoid premature platform complexity.
- Keep reversibility and operational support in view.
- Favor maintainable .NET/TypeScript/Python patterns over cleverness.
- For Microsoft-centric solutions, explicitly assess Entra ID, Azure, Power Platform, Microsoft 365 and Copilot fit.
